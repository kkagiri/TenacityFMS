1. System Overview

The FMS Stock Management module offers comprehensive management of fuel tank inventories, volume history, deliveries, adjustments and automated reconciliation. It integrates real-time data from PTS devices and provides actionable dashboards for site operators and head-office users.

  • Frontend: React & Redux (see src/pages/tankStock/tankStockPage.js).
  • Backend: ASP.NET Core with CQRS pattern (see FMS.Application/Features/TankManagement).
  • Real-time: SignalR hub useTankStockSignalR.

2. End-User Procedures

2.1 Opening Stock

Opening stock represents the measured volume at the start of a business period (usually the first transaction of the day).

  1. Navigate to Tank Stock Dashboard > Stock Adjustment.
  2. Select Opening Stock action.
  3. Fill in tank, amount and date.
  4. Click Submit. A confirmation message appears.

2.2 Closing Stock

Closing stock captures the tank volume at the end of the day.

  1. Open the Stock Adjustment form.
  2. Choose Closing Stock.
  3. Enter the measured volume and timestamp.
  4. Save the record to finalize the day-end position.

2.3 Delivery

Record incoming fuel deliveries to maintain accurate stock counts.

  1. From the dashboard, click Delivery.
  2. Choose the destination tank and specify volume, supplier reference & date.
  3. The system updates TankVolumeHistory with a positive VolumeChange.

2.4 Manual Refill

Manual refills apply when dispensing occurs outside automated PTS integrations.

  1. Go to Manual Refill page (src/pages/manualrefill/manualRefilPage.js).
  2. Select vehicle, tank and fill in volume & meter readings.
  3. Save to generate a FuelRefill entry and update TankVolumeHistory.

2.5 Stock Reconciliation

The reconciliation tool compares expected stock (opening + deliveries – withdrawals) with measured closing stock.

  1. Click Stock Reconciliation on the toolbar.
  2. Review variances. Discrepancies can be auto-corrected by generating Stock Adjustments.
  3. Use the Reconcile button; results store in StockAdjustment and TankVolumeHistory.

2.6 Reporting

Generate PDF/Excel reports of stock movements, consumption trends and variances.

  1. Open Reports dialog.
  2. Select report type (summary, variance, utilization).
  3. Choose date range and site (optional), then Generate.
  4. Status is tracked in StockReport. Completed files can be downloaded from the dashboard.

3. Developer Guide

3.1 Architecture

The Stock module follows a clean-architecture style with CQRS and Mediator pattern.

  • Domain Entities: StockAdjustment.cs, TankVolumeHistory.cs, StockReport.cs, FuelRefill.cs, PumpTransaction.cs.
  • Application Layer: Commands & Queries under FMS.Application/Features/TankManagement.
  • Infrastructure: EF Core repositories & background services.

3.2 Key Entity Relationships

Tank --< TankVolumeHistory >-- StockAdjustment
Tank --< FuelRefill >-- PumpTransaction
User --< StockReport

3.3 Frontend Components

  • tankStockPage.js – main dashboard, SignalR live updates.
  • Adjustment / Reconciliation / Report components under src/components/tankStock.
  • Manual Refill page src/pages/manualrefill.
  • PTS Automation Configuration page src/pages/PTSAutomationConfig.

3.4 SignalR Integration

The hook useTankStockSignalR establishes a connection to /tankStockHub for real-time volume updates. On reconnection the dashboard triggers requestTankDataRefresh().

3.5 Automated Services

  • TankVolumeHistoryService – polls PTS devices and logs every volume change.
  • StockReconciliationJob – nightly job comparing theoretical vs measured stock.
  • ReportGeneratorService – background task creating PDF/Excel stock reports.

3.6 API Endpoints

POST /api/tankstock/opening        (FromQuery) tankId, amount, date
POST /api/tankstock/closing        (FromQuery) tankId, amount, date
POST /api/tankstock/delivery       (Body)     DeliveryDto
POST /api/tankstock/transfer       (Body)     TankTransferDto
POST /api/tankstock/reconcile      (Body)     { siteId?, userId }
GET  /api/tankvolumehistory?from=yyyy-MM-dd&to=yyyy-MM-dd&siteId?
GET  /api/stockreports/:id/download

3.7 Validation & Responses

All endpoints return FMSResponse with success, message, and errors fields.

4. Configuration & Deployment

4.1 appsettings.json

{
  "ConnectionStrings": {
    "FmsDb": "Server=.;Database=FMS;Trusted_Connection=True;"
  },
  "SignalR": {
    "TankStockHubUrl": "/tankStockHub"
  },
  "Reporting": {
    "OutputPath": "wwwroot/reports"
  },
  "TankVolumeHistory": {
    "PollingIntervalSeconds": 60
  }
}

4.2 Environment Variables

  • FMS__DB – connection string override.
  • FMS__REPORT_OUTPUT – path for generated files.

4.3 DevExtreme & Tailwind Setup

All Tailwind classes are prefixed with tw- to avoid conflicts. Font Awesome icons follow the fa-light family.
