🖥️ Frontend Documentation - Notification Feature

Overview

The FMS frontend integrates with the notification system to display real-time alerts and messages to users. This section details the components and processes involved in rendering and managing notifications on the client side.

Key Components

  • fms.frontend/src/pages/notification: This directory contains the main React components responsible for displaying and managing notifications.
  • Redux State Management: Notifications are managed within the Redux store, allowing for centralized state updates and consistent display across the application.
  • SignalR Integration: Real-time notifications are pushed from the backend using SignalR, ensuring immediate updates without page refreshes.
  • DevExtreme UI Components: Notifications are rendered using DevExtreme components, ensuring a consistent look and feel with the rest of the application.
  • Tailwind CSS: Styling for notification components adheres to the Tailwind CSS conventions, using the tw- prefix to avoid conflicts.

User Interface (UI)

The notification UI typically includes:

  • A notification icon (e.g., a bell icon) in the header, often with a badge indicating unread notifications.
  • A dropdown or dedicated page to list all notifications, with options to mark as read, filter, or dismiss.
  • Toast notifications or pop-up alerts for critical real-time events.

Interaction Flow

  1. User logs in, and the frontend establishes a SignalR connection to the backend notification hub.
  2. New notifications are pushed from the backend via SignalR.
  3. The frontend Redux store is updated with the new notification data.
  4. React components re-render to display the new notifications (e.g., updating the badge count, showing a toast).
  5. Users can interact with notifications (e.g., clicking to view details, marking as read), which triggers API calls to the backend to update their status.

📱 Styling Conventions

As per the FMS Frontend Architecture Guide, all Tailwind CSS classes used in notification components must be prefixed with tw- (e.g., <div class="tw-bg-blue-100 tw-p-4">).

FontAwesome icons are used for visual cues, following the pattern "fa-light fa-icon".
