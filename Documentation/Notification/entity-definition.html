📋 Entity Definition & Domain Architecture

🎯 Overview

This document defines the key entities within the FMS notification system, their attributes, and their real-world meaning.

🏗️ Domain Architecture: Events, Alarms, Alerts, and Notifications

The FMS system distinguishes between four critical domain concepts that are often confused but serve distinct purposes

📐 Domain Separation Theory

🔄 Events (Business Occurrences)

Definition: Business occurrences that happen within the system as part of normal operations.

  • Examples: Stock reconciliation completed, delivery recorded, tank transfer executed
  • Characteristics: Expected, part of workflow, informational
  • Domain Layer: Event sourcing patterns, business state changes

🚨 Alarms (System Conditions)

Definition: System-detected conditions that require attention, either automatically triggered by business rules or manually triggered by operators.

  • Examples: Low fuel level detected, high consumption rate, discrepancy threshold exceeded
  • Characteristics: Conditional, require evaluation, have persistence and lifecycle
  • Domain Layer: ActiveAlarm entity with state management (Active → Acknowledged → Resolved)
  • Trigger Types:
    • Policy-Driven: Automatic triggers based on business rules and thresholds
    • Manual: Operator-initiated using Tank.DiscrepancyThreshold for validation

📡 Alerts (Hardware Signals)

Definition: Raw signals from physical hardware devices, particularly PTS (Petrotec Terminal System) devices.

  • Examples: PTS device communication failure, sensor malfunction, probe calibration error
  • Characteristics: Hardware-originated, protocol-specific, require interpretation
  • Domain Layer: PTSAlertRecord entity storing raw device signals

📢 Notifications (User Communications)

Definition: Messages delivered to users through various channels to inform them of Events, Alarms, or Alerts.

  • Examples: Email about low fuel, SMS for critical alarm, system notification for completion
  • Characteristics: Communication mechanism, multi-channel, delivery-focused
  • Domain Layer: Notification entity with delivery tracking and acknowledgment

ActiveAlarm Domain Entity

The ActiveAlarm entity represents persistent alarm state within the domain layer, managing the complete lifecycle of alarm conditions from detection through resolution:

🏗️ Architectural Pattern

Layer: Domain Entity (not DTO, not just persistence)

Purpose: Track alarm lifecycle, maintain business state, enable policy-driven processing

State Flow: Active → Acknowledged → Resolved (with possible escalation paths)

Property Type Business Purpose
AlarmState enum Tracks lifecycle: Active, Acknowledged, Resolved, Escalated
TriggerSource enum Distinguishes Manual vs PolicyDriven vs PTSAlert origins
ThresholdValue decimal? Business rule threshold that triggered the alarm
ActualValue decimal? Measured value that exceeded the threshold
CooldownUntil DateTime? Prevents alarm spam through policy-driven cooldown periods
EscalationLevel int Tracks escalation progression for unacknowledged alarms

Integration Patterns

  • Event → Alarm: Stock reconciliation events can trigger discrepancy alarms when thresholds are exceeded
  • Alert → Alarm: PTS hardware alerts are interpreted and may create alarms requiring attention
  • Alarm → Notification: Active alarms trigger notifications to appropriate recipients based on policies
  • Manual Triggers: Operators can create alarms using Tank.DiscrepancyThreshold for validation

NotificationPolicy: Business Rules Engine

The NotificationPolicy entity serves as a business rules engine that governs notification behavior, delivery, and lifecycle management across the FMS system.

🎯 Policy-Driven Architecture

Core Concept: Instead of hardcoded notification logic, policies provide configurable rules that determine:

  • When: Trigger conditions and cooldown periods
  • Who: Recipient selection and escalation rules
  • How: Delivery channels (email, SMS, system notifications)
  • What: Message templates and formatting
  • Actions: Automatic issue tracker creation and acknowledgment requirements

Policy Resolution Flow

🔄 Multi-Layered Policy Application

  1. Category-Based Selection: NotificationCategoryId filters applicable policies
  2. Site Scoping: Global policies + site-specific policies are merged
  3. Rate Limiting: CooldownMinutes, MaxNotificationsPerHour/Day prevent spam
  4. Channel Control: EnableEmail/Sms/System flags determine delivery methods
  5. Template Application: TitleTemplate, MessageTemplate standardize formatting
  6. Integration Actions: CreateIssueTracker triggers automatic issue creation

Policy Implementation Patterns

Policy Type Use Case Key Configuration
Tank Alarm Policy Critical fuel level alerts High priority, all channels enabled, 30min cooldown, issue tracker creation
PTS Device Policy Hardware communication failures Device-specific scope, SMS enabled, acknowledgment required
Reconciliation Policy Daily stock variance reports Low priority, email only, scheduled delivery, no cooldown
Maintenance Policy Scheduled maintenance reminders Medium priority, email + system, 24hr advance notification

Policy vs. Preference Distinction

  • NotificationPolicy: System-wide business rules and automation (administrator-controlled)
  • NotificationPreference: Individual user preferences that can override policy defaults
  • Hierarchy: Policy → Preference → System Default (most specific wins)

Notification Entity

Represents a single notification event or message intended for a user or a group of users. It captures the content, status, and metadata of a notification.

Attribute Type Description Real-world Meaning
Id int Primary key, unique identifier for the notification. A unique internal reference number for each specific message.
NotificationId string (GUID) Unique identifier for tracking notifications, generated as a GUID. A public-facing unique ID for the notification, useful for external references.
Type string Type of notification (e.g., Alert, Info, Warning, Error, System). Indicates the general nature or severity of the message.
Category string Category for grouping notifications (e.g., Tank, Pump, Vehicle, System, User). Helps in filtering and organizing notifications based on their subject area.
NotificationCategoryId int Foreign key to the NotificationCategory entity. Links to a predefined category for this notification.
Priority string Priority level (e.g., Low, Medium, High, Critical). Indicates the urgency of the notification.
Title string Title or subject of the notification. A short, descriptive headline for the message.
Message string Main message content. The full text of the message.
Data string (JSON) Additional data in JSON format, providing more context. Extra structured information relevant to the notification.
TriggerSource string How the notification was triggered (e.g., Manual, Scheduled, Alarm, System, API). The origin or cause of the notification.
TriggeredBy string ID of the user who triggered the notification (if applicable). The user responsible for initiating the notification.
CreatedAt DateTime When the notification was created. The timestamp when the message was generated by the system.
ScheduledAt DateTime? When the notification should be sent (for scheduled notifications). The planned delivery time for future notifications.
SentAt DateTime? When the notification was actually sent. The actual delivery time of the message.
Status string Current status (e.g., Pending, Sent, Failed, Cancelled). The current state of the notification in its lifecycle.
SendAttempts int Number of send attempts. How many times the system tried to send this notification.
ErrorMessage string? Error message if sending failed. Details about any issues encountered during sending.
SiteId int? Site ID if notification is site-specific. Links the notification to a specific physical site.
TankId int? Tank ID if notification is tank-specific. Links the notification to a specific fuel tank.
VehicleId int? Vehicle ID if notification is vehicle-specific. Links the notification to a specific vehicle.
PtsDeviceId string? PTS Device ID if notification is PTS device-specific. Links the notification to a specific PTS device.
IssueTrackerId int? Issue tracker ID if related to an issue. Links the notification to an entry in the issue tracking system.
AlarmId int? Alarm ID if triggered by an alarm. Links the notification to a specific alarm event.
NotificationPolicyId int? Notification policy ID that governs this notification. Links the notification to the policy that defined its creation and behavior.
IsRead bool Whether this notification has been read by admin. Indicates if the notification has been viewed by an administrator.
ReadAt DateTime? When the notification was marked as read. The timestamp when the notification was marked as viewed.
IsArchived bool Whether this notification is archived. Indicates if the notification has been moved to an archive.
ArchivedAt DateTime? When the notification was archived. The timestamp when the notification was archived.

NotificationGroup Entity

Represents a logical grouping of users or notification types. Notifications can be sent to a group rather than individual users, simplifying management.

Attribute Type Description Real-world Meaning
Id int Primary key, unique identifier for the notification group. A unique internal reference for this collection of users or notification types.
Name string The name of the notification group. A human-readable name for the group (e.g., 'All Administrators', 'Maintenance Team', 'Critical Alerts').
Description string? A brief description of the group's purpose. Explains what this group is for.
SiteId int? The ID of the site this notification group is associated with. Links the group to a specific physical location.
AllowedDeliveryMethods string? Comma-separated list of allowed delivery methods (e.g., 'Email,SMS,InApp'). Specifies how notifications sent to this group can be delivered.
IsActive bool Indicates if the group is currently active and can receive notifications. Whether this group is currently enabled to receive messages.
CreatedBy string The user who created this notification group. The individual who initially set up this group.
CreatedAt DateTime The timestamp when the notification group was created. When this group was first defined in the system.
UpdatedBy string? The user who last updated this notification group. The individual who last modified this group's settings.
UpdatedAt DateTime? The timestamp when the notification group was last updated. When this group's definition was last changed.
Members ICollection<NotificationGroupMember> Collection of members belonging to this group. The list of individuals who are part of this group and will receive its notifications.
PolicyMappings ICollection<NotificationPolicyGroup> Collection of notification policies associated with this group. Links this group to specific rules governing notification behavior.

NotificationPreference Entity

Allows individual users to customize how and when they receive notifications, providing a personalized experience.

Attribute Type Description Real-world Meaning
Id int Primary key, unique identifier for the preference setting. A unique internal reference for this specific user's notification settings.
UserId string The ID of the user whose preferences these are. The specific person whose notification settings are being defined.
NotificationCategoryId int Foreign key to the NotificationCategory entity this preference applies to. The category of messages this setting controls.
DeliveryMethods string Comma-separated list of delivery methods enabled for this category (e.g., 'Email,SMS,System'). How the user wants to receive notifications for this category.
IsEnabled bool Whether notifications for this category are enabled. If the user wants to receive any notifications for this category.
Priority string? Priority level for this category (e.g., Low, Medium, High, Critical). The preferred urgency level for notifications in this category.
QuietHoursStart TimeSpan? Start time for quiet hours (when notifications should be suppressed). The beginning of a period when the user prefers not to receive notifications.
QuietHoursEnd TimeSpan? End time for quiet hours. The end of a period when the user prefers not to receive notifications.
MaxNotificationsPerHour int Maximum notifications per hour for this category (0 = unlimited). A limit on how many notifications of this type the user receives per hour.
MaxNotificationsPerDay int Maximum notifications per day for this category (0 = unlimited). A limit on how many notifications of this type the user receives per day.
RequireAcknowledgment bool Whether to require acknowledgment for notifications in this category. If the user must explicitly confirm receipt of notifications in this category.
CreatedAt DateTime When this preference was created. The timestamp when these notification settings were first defined.
UpdatedAt DateTime? When this preference was last updated. The timestamp when these notification settings were last modified.
CreatedBy string Who created this preference. The user who initially set up these preferences.
UpdatedBy string? Who last updated this preference. The user who last modified these preferences.
