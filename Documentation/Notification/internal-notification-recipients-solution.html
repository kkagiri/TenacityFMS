📋 New Entity: BusinessFunctionNotificationGroup

Entity Structure

public class BusinessFunctionNotificationGroup {
    public int Id { get; set; }

    public string TriggerSource { get; set; }  // "ClosingStock", "AutomatedReconciliation"
    public int GroupId { get; set; }           // Links to NotificationGroup
    public int? SiteId { get; set; }           // null = global, specific = site-only

    public bool IsActive { get; set; }
    public string? AllowedDeliveryMethods { get; set; }  // Override group methods
    public string? MinimumSeverity { get; set; }         // "Critical", "High", etc.

    // Navigation Properties
    public virtual NotificationGroup Group { get; set; }
    public virtual Site? Site { get; set; }
}

✅ Benefits of This Approach

  • Reuses Existing Groups: Leverages NotificationGroup entity and UI
  • Site-Specific Configuration: Different groups per site for same TriggerSource
  • Global + Local: Support for global system admin groups and site-specific groups
  • Flexible Delivery: Override delivery methods per trigger source
  • Severity Filtering: Only trigger for specific severity levels

📋 NotificationGroups vs PolicyGroupRecipients - CLARIFIED

⚠️ Key Difference Explained

They are NOT the same thing, but they work together:

Concept Purpose Usage Context Entity Relationships
NotificationGroups Reusable groups of users/roles Both policy-based and business function notifications NotificationGroup → NotificationGroupMembers
NotificationPolicyGroups Link policies to groups Policy-based notifications ONLY NotificationPolicy ←→ NotificationGroup (many-to-many)
BusinessFunctionNotificationGroups Link trigger sources to groups Internal business function notifications ONLY TriggerSource → NotificationGroup (many-to-many)

✅ How They Work Together

NotificationGroup: "Site 1 - Operations Team"
├── Members: [user1@site1.com, user2@site1.com, "SiteManager" role]
├── Used by Policy: NotificationPolicyGroup (PolicyId=123, GroupId=1)
└── Used by Business Function: BusinessFunctionNotificationGroup (TriggerSource="ClosingStock", GroupId=1)

RESULT: Same group can receive both policy-based alarms AND business function notifications
