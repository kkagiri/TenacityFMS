🚨 Internal Business Function Notification Recipients Analysis

Critical Issue: Poor Recipient Targeting in Internal Notifications

🔴 Current Problem Analysis

❌ Major Issues Identified

  1. Hardcoded Recipients: Internal notifications use hardcoded user IDs like "site-manager"
  2. All-User Fallback: Without DisableFallbackAllUsers=true, notifications go to ALL users
  3. No Group Targeting: Cannot leverage NotificationGroups for business functions
  4. Site Administrator Exclusion: Site owners not automatically subscribed to relevant notifications
  5. No Configuration: Business function recipients cannot be configured without code changes

📋 NotificationGroups vs PolicyGroupRecipients Clarification

🎯 Understanding the Group System

NotificationGroups (Entity-based groups)

  • Purpose: Create reusable groups of users/roles
  • Structure: NotificationGroup → NotificationGroupMembers
  • Usage: Link to policies via NotificationPolicyGroup
  • Scope: Can be site-specific or global

NotificationPolicyGroups (Policy mappings)

  • Purpose: Maps NotificationPolicies to NotificationGroups
  • Structure: NotificationPolicy ←→ NotificationGroup (many-to-many)
  • Usage: Only works when NotificationPolicyId is set
  • Problem: Internal business functions have NotificationPolicyId = null

Group Structure Overview

NotificationGroup (e.g., "Site Managers", "Maintenance Team")
├── NotificationGroupMembers
│   ├── MemberType: "User", MemberId: "user1@company.com"
│   ├── MemberType: "User", MemberId: "user2@company.com"
│   └── MemberType: "Role", MemberId: "SiteManager"
└── NotificationPolicyGroups (Links to policies)
    ├── PolicyId: 123, GroupId: 1
    └── PolicyId: 456, GroupId: 1

❌ ISSUE: Internal business functions cannot use this system
   because they don't have NotificationPolicyId

👤 Site Administrator Subscription Analysis

⚠️ Site Administrator Notification Gap

Site administrators are included in notifications through:

  1. Automatic Resolution: If request.SiteId is provided → Site.SiteAdministratorId added
  2. Manual Subscription: Admin must manually subscribe via UserNotificationPreferences
  3. Policy Recipients: Must be explicitly added to NotificationPolicyRecipients

Problem: No automatic subscription to relevant business function categories!

How Site Administrator Gets Notifications

✅ WORKS: Site admin gets notifications if SiteId is set in internal business functions
❌ LIMITATION: Fixed delivery methods, no user preference consideration

New Entity: BusinessFunctionNotificationGroup

public class BusinessFunctionNotificationGroup {
    public int Id { get; set; }

    [Required]
    public string TriggerSource { get; set; }  // "ClosingStock", "AutomatedReconciliation"

    public int GroupId { get; set; }
    public virtual NotificationGroup Group { get; set; }

    public int? SiteId { get; set; }  // null = global, specific = site-only
    public virtual Site? Site { get; set; }

    public bool IsActive { get; set; } = true;

    [MaxLength(100)]
    public string? AllowedDeliveryMethods { get; set; }  // Override group methods

    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
    public string CreatedBy { get; set; }
}

Enhanced NotificationRecipientResolver

// Add to NotificationRecipientResolver.ResolveRecipientsAsync()

// 3a. Business Function Groups (if NotificationPolicyId is null)
if (request.NotificationPolicyId == null && !string.IsNullOrEmpty(request.TriggerSource)) {
    var businessFunctionGroups = await GetBusinessFunctionGroupsAsync(
        request.TriggerSource, request.SiteId, cancellationToken);

    foreach (var bfGroup in businessFunctionGroups) {
        var groupMembers = await ResolveGroupMembersAsync(bfGroup.Group, cancellationToken);
        foreach (var member in groupMembers) {
            if (!addedUserIds.Contains(member.UserId)) {
                recipients.Add(member);
                addedUserIds.Add(member.UserId);
            }
        }
    }
}
