Modules and Services - Notification Feature

Back to Main Documentation

Overview

The notification feature in FMS is implemented across various modules and services, following a layered architecture. This document details the key components and their responsibilities.

Backend Modules

FMS.Domain.Entities

  • Purpose: Defines the core domain entities related to notifications.
  • Key Entities:
    • Notification: Represents a single notification event.
    • NotificationGroup: Represents a logical grouping of notifications or recipients.
    • NotificationPreference: Stores user-specific notification settings.

FMS.Application/Features/Notification

  • Purpose: Contains the application-specific logic for notifications, including Commands, Queries, DTOs, and Handlers.
  • Key Components:
    • Commands: (e.g., CreateNotificationCommand, MarkNotificationAsReadCommand) - For actions that modify notification state.
    • Queries: (e.g., GetNotificationsQuery, GetNotificationGroupsQuery) - For retrieving notification data.
    • DTOs: Data Transfer Objects for transferring notification data between layers.
    • Handlers: Implementations for processing commands and queries.
    • Services: (e.g., NotificationService) - Business logic for creating, managing, and dispatching notifications.

FMS.BackgroundServices/FMS/Notification

  • Purpose: Handles background processing related to notifications, such as sending real-time updates or processing scheduled notifications.
  • Key Components:
    • NotificationProcessor: A background service that listens for notification events and dispatches them to appropriate channels (e.g., SignalR).
    • Scheduled Tasks: For sending digest emails or other periodic notification types.

FMS.WebClient/Controllers

  • Purpose: Exposes RESTful API endpoints for the frontend to interact with the notification system.
  • Key Controllers:
    • NotificationController: Handles requests related to individual notifications (e.g., fetching, marking as read).
    • NotificationGroupController: Manages notification groups (e.g., creating, updating, deleting).

FMS.Persistence

  • Purpose: Manages data access for notification-related entities.
  • Key Components:
    • Repositories: (e.g., INotificationRepository, NotificationRepository) - Abstractions for data operations.
    • Entity Configurations: Defines the mapping of notification entities to the database schema.
    • GPSDataContext: The database context that includes notification entities.

Frontend Module

fms.frontend/src/pages/notification

  • Purpose: Contains the React components and client-side logic for displaying and interacting with notifications.
  • Key Components:
    • Notification List Component: Displays a list of notifications.
    • Notification Detail Component: Shows details of a specific notification.
    • Notification Settings Component: Allows users to configure their notification preferences.
    • SignalR Client: Manages the real-time connection to the backend NotificationHub.
